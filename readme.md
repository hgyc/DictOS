# DictOS

Мини-ОС х86, которая грузится с образа дискеты и
работает как англо-финский словарь. 
Загрузчик на ассемблере в
512 байт, ядро на C без стандартной библиотеки, без обращений к BIOS после
перехода в защищённый режим.

## Что умеет

Загрузчик спрашивает, слова на какие буквы загружать: на экране строка алфавита,
нажатие клавиши включает или выключает букву. После Enter он читает ядро со второй
дискеты и переводит процессор в защищённый режим. Ядро работает как командная
оболочка, целиком управляемая прерываниями клавиатуры.

| Команда | Описание |
|---|---|
| `info` | Автор, средства разработки, включённые в загрузчике буквы |
| `dictinfo` | Направление перевода, общее число слов и число загруженных |
| `translate <слово>` | Бинарный поиск по словарю; различает «слова нет» и «слово не загружено» |
| `wordstat <буква>` | Количество загруженных слов на указанную букву |
| `anyword [буква]` | Случайное слово и его перевод |
| `shutdown` | Выключение машины через порт ACPI |

## Сборка и запуск

Поддерживаются два набора инструментов. Загрузчик в обоих случаях один и тот же —
ассемблер в синтаксисе AT&T.

**Windows (MSVC, ядро в формате PE)** — из консоли *x86* Native Tools Command Prompt:

```
build.bat
qemu-system-i386 -fda boot.img -fdb kernel.img
```

**Linux (GCC, плоское ядро)**:

```
sudo apt install yasm gcc-multilib qemu-system-x86
sh build.sh
qemu-system-i386 -fda boot.img -fdb kernel.img
```

Оба скрипта дополняют образы до 1 474 560 байт

## Как это устроено

### Последовательность загрузки

BIOS читает нулевой сектор диска A по адресу `0x7C00` и передаёт туда управление,
если сектор заканчивается сигнатурой `0xAA55`. Дальше:

1. Сегментные регистры обнуляются, стек ставится на `0x7C00` — он растёт вниз, в
   свободную память под кодом, поэтому затереть код не может.
2. 26 байт по адресу `0x9000` хранят маску включённых букв. Это и есть весь
   механизм передачи параметров между загрузчиком и ядром: обе стороны
   договорились об адресе, а плоская модель памяти делает линейный адрес равным
   физическому.
3. Ядро читается с диска B по одному сектору через `int 0x13`, линейный номер
   сектора пересчитывается в координаты CHS (18 секторов на дорожке).
4. Процессор переводится в защищённый режим: `cli`, `lgdt`, открытие линии A20
   через порт `0x92`, бит PE в `CR0` и дальний переход, который перезагружает `CS`
   и сбрасывает конвейер.
5. Управление уходит ядру по адресу `0x10000`, сегменты плоские на 4 ГБ.

### Загрузка ядра в формате PE

Сборка под MSVC дает PE-образ, поэтому загрузчик разбирает
заголовки сам, вместо того чтобы полагаться на зашитые адреса. Читает четыре
сектора, по смещению `0x3C` находит PE-заголовок, берёт из него `ImageBase`, число
секций и таблицу секций, вычисляет реальный размер файла, дочитывает остаток и
раскладывает каждую секцию по адресу `ImageBase + VirtualAddress`. Перед
копированием `SizeOfRawData` байт секция заполняется нулями на `VirtualSize` —
именно так обнуляется `.bss`, которой в файле нет вообще.

Благодаря этому загрузчик продолжает работать, когда ядро растёт и компоновщик
переносит секции по другим адресам.

### Ядро

`kmain` инициализирует состояние, строит таблицу прерываний,
открывает линию IRQ1 и уходит в вечный `hlt`; вся работа происходит внутри
обработчика прерывания клавиатуры. 

Отдельные решения:

- **Таблица прерываний** строится во время выполнения, все 256 векторов заполнены
  заглушкой, чтобы неожиданное исключение возвращалось, а не приводило к тройной
  ошибке; вектор `0x09` указывает на naked-обёртку с `pusha`, вызовом, `popa` и
  `iretd`.
- **Вывод на экран** идёт прямо в `0xB8000`, знакоместо трактуется как одно
  16-битное слово: символ в младшем байте, атрибут цвета в старшем. Прокрутка
  экрана вместо очистки, как в терминале Unix.
- **Клавиатура** разбирает скан-коды набора 1 по таблице на 128 байт, отслеживает
  Shift для ввода заглавных, ограничивает строку 40 символами и обрабатывает
  Backspace.
- **Словарь** из 508 отсортированных пар, поиск бинарный. Финские `ä` и `ö`
  хранятся байтами CP437 `0x84` и `0x94`, поскольку в текстовом режиме VGA одно
  знакоместо — это один байт.
- **Генератор случайных чисел** линейный конгруэнтный, начальное значение из часов
  реального времени, в состояние подмешиваются скан-коды нажатий; используется
  командой `anyword`.
- Количество слов на каждую букву считается один раз при старте, поэтому
  `wordstat` — это одно обращение к массиву, а не проход по словарю.

### Карта памяти

```
0x00000   таблица векторов реального режима и данные BIOS
0x07C00   загрузчик (512 байт), отсюда стек растёт вниз
0x09000   26 байт маски букв, общие с ядром
0x10000   образ ядра: код, данные, bss
0x90000   стек ядра (растёт вниз)
0xB8000   текстовый буфер VGA, 80x25, два байта на знакоместо
```

## Состав репозитория

```
bootsect.asm     загрузчик, YASM с парсером GAS (синтаксис AT&T)
kernel.cpp       ядро, C без стандартной библиотеки (сборка MSVC)
build.bat        сборка под Windows (cl.exe + link.exe)
build.sh         сборка под Linux (gcc)
```

## Упрощения

Это учебное ядро:

- Контроллер прерываний оставлен с настройками BIOS, поэтому аппаратные прерывания
  накладываются на векторы исключений процессора. Настоящее ядро перенастраивает
  его на векторы `0x20`–`0x2F` при инициализации.
- Разбор команды и поиск по словарю выполняются внутри обработчика прерывания при
  запрещённых прерываниях. Здесь это безопасно, но неправильно в общем случае:
  обработчик должен складывать скан-коды в очередь, а разбирать их основной цикл.
- Нет управления памятью, процессов и файловой системы. Всё работает в нулевом
  кольце.
- Загрузчик PE использует промежуточный буфер, адресуемый одним сегментом, поэтому
  ядро должно помещаться в 64 КБ.
